### 戰鬥中保護與鎖檔（2026-10-10 碧青洞窟事故後加，`ass.py` + `tools/gui/battleguard.py`）
- 事故：15:31 步 3 BOSS 戰開始 1 秒後，外掛設定（當時是「自動逃跑」）被打開 → DKB0 脫隊、單獨打了步 5 的 BOSS，其他 4 人落後一步（日誌多次「DKB0離開了隊伍」）。**戰鬥中不可開外掛面板 / 改任何勾選。**
- `get` / `set` / `pet` 一律先判斷是不是戰鬥中，是 → **不開面板、不點任何東西**，等戰鬥結束（連續 2 次讀到非戰鬥、每 1.5 秒讀一次，最多 `BATTLE_WAIT` = 90 秒）再做；逾時 **退出碼 8**。**`--no-wait`**：戰鬥中不等，直接退出碼 8。
- 「戰鬥中」的兩個來源（任一成立）：① **戰鬥畫面像素**（`battleguard.screen_in_battle`：上方棕框外框 9 點全中，或頭上 VS 牌綠框 706,295 ≈ 122,227,0 → 快速戰鬥也算）；② **`quest.py` 的鎖檔** `tools/.cache/battle.lock`（JSON：pid、start 時間、模式）：quest.py（預設 / `--solo` / `--fight` 全模式）一進戰鬥就寫、回到主畫面 / 對話 / 領獎 / 巡路就刪、程式結束（`finally`）也刪；ass.py 只認「pid 還活著且 30 分鐘內」的鎖（Windows 用 OpenProcess 判斷 pid，不用 `os.kill(pid, 0)`，那在 Windows 會送 Ctrl-C），死鎖 / 過期鎖自動清掉。
- 外掛面板已經開著時視為不在戰鬥（戰鬥中外掛面板打不開）。`quest.py` 啟動時的 `ass.get_states` 也受保護（遇到戰鬥會先等）。
- 注意：`ass.py` 手動跑時，如果遊戲剛好一場快速戰鬥（約 2~3 秒）剛結束，連續 2 次非戰鬥的判斷會多等 3 秒左右。
